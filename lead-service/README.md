# lead-service

Приём заявок с am-fabrika.ru и из лид-форм VK. `POST /api/lead` пишет заявку в таблицу `leads` (та же PostgreSQL, что у Directus), письмо менеджеру уходит через очередь с повторами, в MAX — уведомление «Новая заявка №N с сайта» с кнопкой «Открыть заявку» на карточку в админке, без персональных данных.

Повтор сайта за 10 минут возвращает `201 {id}` сохранённой заявки без новой строки и уведомления. Сравниваются тип, телефон без оформления (`+7`, `8` и 10 цифр российского номера без `+` приводятся к одному значению), компания, имя, город, `need` и `need_extra`, включая выбранную модель. Международный префикс с явным `+` сохраняется. Изменение содержания создаёт новую заявку; IP, страница, UTM и версия согласия не входят в сравнение. В базе сохраняется исходное оформление телефона. `repo.insertLead(lead)` возвращает `{id, created}`: уведомление запускается только при `created: true`. Проверка и вставка выполняются в одной транзакции с advisory lock, новые колонки и права не требуются.

**По умолчанию выключен.** Хранить заявки ООО может только после уведомления Роскомнадзора (152-ФЗ, ст. 22). Пока `LEADS_ENABLED` не равно `true`, сервис не подключается к базе, ничего не отправляет и отвечает на `POST /api/lead` кодом 503 — форма на сайте показывает телефон менеджера.

## Заявки из лид-форм VK

Реклама VK с лид-формой ведёт не на сайт: человек оставляет имя и телефон в форме внутри VK, заявка остаётся в кабинете. Сервис раз в минуту забирает 50 последних заявок форм из `VK_LEAD_FORM_IDS` через API VK Рекламы (`src/vk-leads.mjs`), пишет новые в `leads` с типом `vk` и шлёт в MAX «Новая заявка №N из VK» — так же, как заявки сайта, без персональных данных. Повтор не записывается: номер заявки VK лежит в уникальной колонке `external_id`, и уже записанные заявки сервис не пытается вставить снова — каждая такая попытка тратила бы номер из последовательности `leads.id` (24.10.2026 после № 7 пришла № 1484).

Что куда попадает: имя, телефон, город — в свои колонки; ответы на вопросы формы — в `need` («Когда нужен диван: В ближайший месяц»); кампания и объявление — в `utm` (`utm_campaign`, `utm_content`). В заявке нет, на какой диван откликнулся человек, поэтому для новых заявок сервис берёт само объявление (`GET /api/v2/banners.json`): заголовок идёт в начало `need` («Объявление «Битва за диван отменяется»; Когда нужен диван: …»), ссылка на картинку — в `need_extra`, в MAX — заголовок в тексте и картинка вложением. Не ответил VK — заявка пишется без объявления; MAX не принял картинку — сообщение уходит без неё; время заявки в VK — в `created_at` и `consent_at`; `consent_version` — `vk-form-<номер формы>`, текст согласия VK собирает для каждой формы из реквизитов в её настройках.

Доступ к API выдаёт VK: «Настройки → Общие → Доступ к API → Запросить доступ к API». `client_secret` показывают один раз на 10 минут. Токен живёт сутки и обновляется сам; одновременно у аккаунта может быть не больше 5 токенов, при упоре сервис удаляет старые и берёт новый.

## Заявки с баннеров сайта

Объявления с баннерами (Директ и другие) ведут на главную с `utm_content=<метка>`: `sofa-1` … `sofa-7`, `bed-8` … `bed-11`. Метки, надписи баннеров, товары и цены — в `src/ad-banners.json` (`src/ads.mjs`). Сайт по той же метке показывает над формой прайса товар с баннера и цену, у него копия каталога — `frontend/src/lib/ad-banners.json`; `npm test` проверяет, что копии совпадают. Новый баннер: строка в оба файла, картинка 1:1 в `frontend/public/ads/<метка>.jpg`, чистое фото 4:3 в `frontend/public/ads/foto/<метка>.webp`.

Заявка с известной меткой получает то же, что заявка VK с объявлением: в начале `need` — «Баннер «Кот одобрил, дети не сломали» — серый раскладной диван, от 128 000 ₽», в начале `need_extra` — «Картинка объявления: https://am-fabrika.ru/ads/sofa-2.jpg» (ответы квиза остаются после них), в MAX — строка баннера в тексте и картинка вложением. Незнакомая метка ничего не меняет. Метки сайт берёт из последнего рекламного захода в этой вкладке (`frontend/src/scripts/form.js`).

Если человек явно выбрал модель, price-форма передаёт `need_extra` с префиксом `Модель: `. В этом случае старый баннер не добавляется в обращение и MAX, выбранная модель сохраняется целиком. UTM остаются в заявке как источник перехода.

## Эндпоинты

| | |
|---|---|
| `POST /api/lead` | JSON до 10 КБ: `{type, fields, consent: {version}, source_page?, utm?}` → `201 {id}` |
| `GET /api/health` | `200 {ok: true}` |

Отказы `POST /api/lead`: 503 `leads_disabled` · 429 больше 5 запросов с адреса за 10 минут · 415 не JSON · 413 тело больше 10 КБ · 400 `bad_json` или `invalid` со списком `fields` · 422 `rejected` (заполнено скрытое поле `website`), `consent_required` или `consent_version_unknown` (версии нет в списке опубликованных) · 500 ошибка базы.

Проверки полей повторяют формы. Прайс: компания/ИНН, имя, телефон (от 10 цифр), город, «что нужно» из четырёх вариантов; строка только из цифр считается ИНН и должна иметь 10 или 12 цифр. Квиз: имя и телефон; город и ответы шагов 1–2 можно пропустить, ответы пишутся в `need` и `need_extra`.

## Версии согласия

Заявка сохраняется, только если `consent.version` есть в `src/consent-versions.mjs`. По версии в заявке восстанавливается текст, на который согласился человек, поэтому каждый опубликованный текст лежит в `clients/sf-sofa/legal/` или в истории git.

Новый текст согласия:

1. Сохранить текст в `clients/sf-sofa/legal/`, версия — дата изменения.
2. Добавить дату в `src/consent-versions.mjs`, выложить сервис.
3. Поменять `CONSENT_VERSION` в `frontend/src/scripts/consent-version.js`, выложить сайт. Формы начнут слать новую версию, окно о cookie спросит посетителей заново.
4. Когда старый текст больше не принимается, убрать его дату из списка.

Сервис выкладывать раньше сайта, иначе заявки с новой версией получат 422. `npm test` проверяет, что версия сайта есть в списке.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `LEADS_ENABLED` | `true` — приём включён, любое другое значение — выключен |
| `DATABASE_URL` | `postgres://lead_service:<пароль>@db:5432/<база>`, нужна только при включённом приёме. Пароль лучше из `openssl rand -hex 24` — без символов, требующих экранирования в URL |
| `SMTP_HOST` `SMTP_PORT` `SMTP_USER` `SMTP_PASS` `MAIL_FROM` `MAIL_TO` | письмо менеджеру. Порт 465 — TLS сразу, другой — только через STARTTLS. Не задана хоть одна — почта выключена, в логе одна строка об этом |
| `MAX_BOT_TOKEN` `MAX_CHAT_ID` | уведомление в чат MAX. Не заданы — не отправляется |
| `MAX_API_URL` | по умолчанию `https://platform-api2.max.ru` |
| `VK_ADS_CLIENT_ID` `VK_ADS_CLIENT_SECRET` | доступ к API кабинета VK Рекламы. Не заданы — VK не опрашивается |
| `VK_LEAD_FORM_IDS` | номера лид-форм через запятую, сейчас `1026922` («SF розница — расчёт под размер») |
| `VK_POLL_SECONDS`, `VK_ADS_API_URL` | 60 и `https://ads.vk.ru` |
| `ADMIN_URL` | адрес админки для кнопки «Открыть заявку», compose берёт его из `PUBLIC_URL`. Не задан или не адрес — сообщение уходит без кнопки |
| `NODE_EXTRA_CA_CERTS` | путь к корневому сертификату Минцифры (Russian Trusted Root CA). `platform-api2.max.ru` подписан им, без файла Node соединение отвергнет. На сервере файл лежит в `infra/certs/`, compose монтирует его и задаёт переменную |
| `PORT` | 8080 |
| `RATE_LIMIT_MAX`, `RATE_LIMIT_WINDOW_SECONDS` | 5 и 600 |

В логах — только номер заявки, статус и код ошибки.

## Как включить

1. Уведомление в РКН подано, тексты на /politika и /soglasie вставлены.
2. Создать роль базы от владельца таблицы `leads`: команда в шапке `sql/grant.sql`.
3. В `infra/.env` задать `LEAD_DB_PASSWORD`, SMTP и MAX, затем `LEADS_ENABLED=true` и `docker compose up -d lead-service`.
4. Отправить тестовую заявку с формы: строка в админке «Заявки», письмо менеджеру, сообщение в MAX.

Выключить: `LEADS_ENABLED=false`, `docker compose up -d lead-service`.

## Тесты

`npm test` — без базы. Для интеграционных тестов `DATABASE_URL` должен указывать на изолированную тестовую базу с таблицей `leads`; живую базу не использовать. Проверяются параллельные повторы, оформление телефона, разные обращения, окно 10 минут и очередь; под ролью `lead_service` — также права. Удалить тестовые строки эта роль не может — номера будут в выводе, изолированную базу удаляет её владелец.
